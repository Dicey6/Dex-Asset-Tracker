Dyorly — Full Backend & API Integration Instructions

I have the following APIs already configured in my project:

- Birdeye API key — already in ".env"
- Helius API key — already in ".env"
- Solscan API key — already in ".env"
- DexScreener — already hardcoded/configured in the project

I am using normal HTML, CSS and JavaScript for the frontend.

I do NOT want the frontend converted to React, Next.js, Vue, or another frontend framework.

The project currently does not have a backend, so build the backend as part of this implementation.

Use:

- Vanilla HTML/CSS/JavaScript → frontend
- Python + FastAPI → backend
- Render → FastAPI hosting
- Supabase → database + authentication
- Helius → Solana/on-chain analytics
- Birdeye → market/trading analytics
- Solscan → blockchain verification/research
- DexScreener → DEX/token enrichment
- Telegram Bot API → future watchlist alerts

---

1. Overall Architecture

Build the project using this architecture:

                         USER
                           │
                           ▼
                  Dyorly Frontend
                 HTML/CSS/JavaScript
                           │
                           │ HTTPS
                           ▼
                  FastAPI Backend
                       Render
                           │
             ┌─────────────┼─────────────┐
             │             │             │
             ▼             ▼             ▼
          Helius        Birdeye       Solscan
             │             │             │
             └─────────────┼─────────────┘
                           │
                     DexScreener
                           │
                           ▼
                       Supabase
                    ┌──────┴──────┐
                    │             │
                PostgreSQL      Auth

The frontend will eventually be hosted on Vercel.

The FastAPI backend will be hosted on Render.

Supabase will provide the database and authentication.

The frontend communicates with FastAPI through normal HTTPS API requests.

Vercel does NOT need a special integration with Render.

For example:

Dyorly frontend
      ↓
https://api.dyorly.com/api/tokens/analyze
      ↓
FastAPI on Render
      ↓
Helius / Birdeye / Solscan / DexScreener
      ↓
FastAPI normalizes the data
      ↓
Frontend receives JSON

20. Watchlist Monitoring

Create a backend monitoring service.

It should:

1. Retrieve current prices for watchlisted tokens.
2. Compare against the correct reference price.
3. Detect a 20% increase.
4. Trigger an alert.
5. Prevent duplicate alerts.
6. Update monitoring state.

Use efficient polling, batching, caching or provider real-time/webhook functionality where appropriate.

Do not continuously make expensive API requests unnecessarily.

22. FastAPI ↔ Vercel

The frontend will eventually be hosted on Vercel.

The backend will be hosted on Render.

They communicate through HTTPS.

Example:

Vercel frontend
https://dyorly.com
        ↓
HTTPS request
        ↓
Render backend
https://api.dyorly.com

The frontend JavaScript should call the FastAPI API URL.

Example:

fetch(`${API_BASE_URL}/api/tokens/analyze`, {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        ca: tokenAddress
    })
});

Do not hardcode API keys into the frontend.

27. API Efficiency

Dyorly will make many analytics requests, so avoid unnecessary API consumption.

Implement:

- Caching
- Request deduplication
- Reasonable cache expiration
- Provider-specific timeouts
- Retry handling
- Rate-limit handling
- Batch requests where supported
- Real-time/webhook functionality where appropriate

Do not repeatedly request the same token information if it has not changed.

Especially optimize Birdeye usage because API usage/compute limits need to be respected.

---

28. Error Handling

If Birdeye fails, Dyorly should not necessarily fail completely.

If Helius fails, return whatever other information is safely available.

If Solscan fails, continue using Helius/Birdeye where possible.

If DexScreener fails, continue using the other providers.

Return missing fields as:

null

rather than inventing values.

Handle:

- Invalid CA
- Invalid wallet address
- Token not found
- Wallet not found
- API timeout
- API rate limit
- Provider downtime
- Missing metadata
- Missing PnL
- Missing holder information

---

29. Important API Source Rules

Use the providers according to their strengths:

Helius

Source of truth for on-chain activity.

Birdeye

Source of truth for market/trading analytics where available.

DexScreener

DEX/token enrichment and cross-checking.

Solscan

Blockchain verification and research.

Supabase

Application database + authentication.

Do not unnecessarily query multiple providers for the same information.
